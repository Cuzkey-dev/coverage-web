# Coverage Web

画像から重要度関数 Φ を設計し、二輪移動ロボットの**被覆制御シミュレーション**を実行・保存・比較できる Web アプリケーションです。

修士研究（東京都立大学 児島研究室・ロボットマスゲームにおける被覆制御）で使っている MATLAB のシミュレーションを、
**ブラウザ上で誰でもパラメータを変えて試せるツール**として作り直しています。

## なぜ作るか

被覆制御では、環境のどこを重視するかを表す重要度関数 Φ の設計が結果を大きく左右します。
しかし Φ を変えるたびにスクリプトを書き換えて実行し直す必要があり、
**条件を変えた実行どうしを見比べる**のに手間がかかっていました。

このツールでは次ができます。

- 画像をアップロードし、エッジ検出のパラメータを触りながら Φ をその場で作る
- その Φ でシミュレーションを実行し、結果を保存する
- 過去の実行と並べ、パラメータの差分と評価値を対比する

## 機能

- [x] シミュレーションのコア（Voronoi 分割・重み付き重心・Lloyd 法）
- [x] 画像からの Φ 生成（Sobel / Scharr / Canny、ぼかし・閾値・グリッド解像度・下駄を調整）
- [x] ブラウザ上での描画（Φ のヒートマップ、ロボットの軌跡と現在位置、再生／一時停止／ステップ送り、評価値の折れ線）
- [x] 実行結果の保存・一覧・詳細の再生
- [x] 実行どうしの比較（変わったパラメータだけを強調、評価値の推移を重ねる）
- [x] お手本の実行を最初から置く（`npm run db:seed`）
- [ ] 認証（**未実装**。誰でも保存でき、保存された実行は誰からも見える）
- [ ] 共有 URL（**未実装**。`Run.isPublic` はスキーマにあるだけで使っていない）

## 画面

| パス | 内容 |
| --- | --- |
| `/` | 使い方の 3 ステップと、最近保存した実行 |
| `/new` | 画像のアップロード（ドラッグ＆ドロップ可）→ Φ のプレビュー → 実行 → 再生 → 保存 |
| `/runs` | 保存済み実行のカード一覧。2 件チェックして比較へ |
| `/runs/[id]` | パラメータと結果の再生 |
| `/compare?a=…&b=…` | 2 件を左右に並べて比較 |

画像を持っていなくても「サンプル画像を使う」で図形の画像から試せます。
`npm run db:seed` を流しておくと、比較をすぐ試せるお手本の実行が 2 件入ります。

### 公開したときの扱い（認証が無いことの結果）

認証を入れていないので、次のように振る舞います。**誰が保存したかは分からない**前提で読んでください。

- 保存した実行は**誰からも見える**。他人に見せたくないものを入れない
- 削除できるのは**保存したのと同じブラウザ**だけ。ブラウザごとに乱数（所有者トークン）を
  localStorage に持ち、それが一致する実行だけ消せる。本人確認ではないので、
  「うっかり他人の実行を消す」を防ぐ仕切りであって認証の代わりではない
- `npm run db:seed` で入れたお手本は所有者トークンを持たないので、**誰も消せない**
- 保存できる実行は全部で 200 件まで。超えると訪問者が作った古いものから消える（お手本は残る）

## 設計メモ

- **シミュレーションのコアと Φ 生成は純粋関数に切り出す**（`src/lib/coverage/`）。
  React や DB に依存させないことで、そのままユニットテストの対象にできる。
  - `geometry.ts` … Voronoi の担当決め、重み付き重心、Lloyd 法の 1 ステップ
  - `phi.ts` … 画像 → グレースケール → ガウシアン → 勾配 → エッジ → グリッド化 → 正規化
  - `simulate.ts` … シード付き初期配置、`lloydStep` の反復、評価値 H の計算
  - `runResult.ts` … 保存する JSON の形と間引き
  - `params.ts` / `render.ts` … パラメータの差分、ヒートマップの色
- **距離比較には平方根を使わない**。順序さえ保てればよく、格子の全セルを走査するため効果が大きい。
- **担当セルを持たないロボットは動かさない**。移動させる根拠がないため、現在地を保持する。
- **評価値は位置関数 H = Σ_q min_i ‖q − p_i‖² Φ(q)**。各セルについて担当ロボットまでの距離の 2 乗に Φ を掛けて足し上げる。
  Lloyd 法はこれを単調に減らす。グリッド解像度が違う実行どうしは絶対値をそのまま比べられない。
- **Canny の閾値は最大勾配を 1 とした相対値**で受け取る。画像のコントラストに依らず同じスライダーで扱えるようにするため。
- **Φ の下駄（floor）**。Φ = floor + (1 − floor) × 正規化したエッジ強度。0 にするとエッジの無い領域を誰も担当しなくなるので、既定で小さな値を入れる。
- **計算量の上限は UI で縛る**。`weightedCentroids` と H の計算は毎ステップ全セル × 全台数を走査するので、
  グリッドは 1 辺 128、台数 40、ステップ 300 を上限にしている（この上限で約 0.5 秒）。実行は 16ms ずつ区切って回し、画面を固めない。
  画像は長辺 512 画素に縮めてからエッジ検出する。
- **実行結果は当面 JSON カラムで持つ**。`Run.result` に入れるのは Φ そのもの・間引いた位置履歴・全ステップの評価値・元画像のサムネイル。
  元画像は保存しないので、再生に必要な Φ を結果側に持たせる。
  位置履歴は最大 121 フレームに間引く（先頭と最終は必ず残し、間は等間隔）。評価値は 1 ステップ 1 数値なので全部残す。
  40 台 × 300 ステップでも 200KB 弱に収まる。
- **DB を読むページは `force-dynamic`**。ビルド時に DB へ接続しないため。
- **削除は所有者トークンで仕切る**。認証を入れずに公開すると誰でも他人の実行を消せてしまう。
  ブラウザごとの乱数を `Run.ownerToken` に持たせ、削除は `deleteMany({ where: { id, ownerToken } })` で行う。
  条件が合わなければ 0 件削除で終わるので、他人の実行やお手本は決して消えない。
  一覧で「消せる実行にだけ削除ボタンを出す」ための突き合わせもサーバー側でやり、トークンは画面へ配らない。
- **エッジ検出のボタン群は `<label>` で囲まない**。`<label>` は最初の操作要素に紐づくため、
  囲むと Sobel ボタンの読み上げ名が「エッジ検出Sobel…」になる。`role="group"` ＋ `aria-labelledby` で組む。
- **サンプル画像は canvas を使わずに作る**（`sampleImage.ts`）。画面と seed スクリプトの両方から
  同じ画像を使いたいので、Node でも動く純粋関数にしてある。
- **開発用のローカル PostgreSQL**。手元に本番 DB が無くても動かせるよう、`npm run db:local` で
  [embedded-postgres](https://github.com/leinelissen/embedded-postgres) を `.local-db/` に立てる（git 管理外）。
  2026-09-05 時点の `.env` はこのローカル DB を指している。Neon を使うときは `DATABASE_URL` を差し替えて `npm run db:push` する。

## 開発

```bash
npm install
cp .env.example .env   # DATABASE_URL を設定する（ローカル DB なら下の db:local の URL）
npm run db:local       # 手元に PostgreSQL が無いとき。別ターミナルで動かしたままにする
npm run db:push        # スキーマをデータベースへ反映
npm run dev
```

| コマンド | 内容 |
| --- | --- |
| `npm run dev` | 開発サーバー |
| `npm test` | テスト実行 |
| `npm run typecheck` | 型検査 |
| `npm run lint` | Lint |
| `npm run build` | 本番ビルド |
| `npm run db:local` | 開発用ローカル PostgreSQL（`postgresql://postgres:password@127.0.0.1:54329/coverage`） |
| `npm run db:push` | スキーマを DB へ反映 |
| `npm run db:seed` | お手本の実行を DB に入れる（何度流しても増えない） |
| `npm run db:studio` | Prisma Studio でデータを確認 |

## 公開する（Vercel + Neon）

1. **データベースを用意する。** [Neon](https://neon.tech) でプロジェクトを作り、接続文字列を控える。
   サーバーレスから繋ぐので、ホスト名に `-pooler` が入った**プール側**の URL を使う
   （1 リクエストごとに接続を張るため、直結だと接続数を使い切る）。
   レイテンシを詰めるなら、Vercel のリージョンと近い場所に作る。
2. **スキーマを流す。** 手元の `.env` の `DATABASE_URL` をその URL にして `npm run db:push`、
   続けて `npm run db:seed`（お手本を入れる）。
3. **Vercel に載せる。** GitHub リポジトリを Import し、環境変数 `DATABASE_URL` に同じ URL を設定する。
   ビルド設定は既定のままでよい（`postinstall` の `prisma generate` が走る）。
4. **確かめる。** `https://<デプロイ先>/api/health` が
   `{"status":"ok","database":"ok","runs":2}` を返せば、アプリと DB の両方が生きている。
   `database: "unreachable"` なら `DATABASE_URL` を見直す。
