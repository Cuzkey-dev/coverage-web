# 開発・運用ガイド

このリポジトリは、Coverage Webの画面、結果の保存・比較、計算サービスへのAPI連携を管理します。アプリの概要と使い方は[README](../README.md)を参照してください。

## ローカル環境

Node.jsとnpm、PostgreSQLを用意します。新規シミュレーションの実行には、別途管理する計算サービスのURLと認証トークンが必要です。計算エンジンはこのリポジトリには含まれません。

```bash
npm install
cp .env.example .env
```

PowerShellでは、コピーに`Copy-Item .env.example .env`を使用できます。`.env`に次の環境変数を設定します。

| 変数 | 用途 |
| --- | --- |
| `DATABASE_URL` | PostgreSQLへの接続文字列。Neonではプール接続を使用 |
| `COVERAGE_ENGINE_URL` | 計算サービスのURL |
| `COVERAGE_ENGINE_TOKEN` | 計算サービスの認証トークン |

これらはサーバー専用です。`NEXT_PUBLIC_`を付けず、値をGitやログに記録しないでください。

手元にPostgreSQLがない場合は、別のターミナルで`npm run db:local`を起動し、`.env.example`に記載のローカル接続文字列を設定できます。新しい開発用データベースにスキーマを作成してから、アプリを起動します。

```bash
npm run db:push
npm run dev
```

`db:push`は初回のスキーマ作成や変更時に使用します。お手本データが必要な場合は、初回に限り`npm run db:seed`を実行してください。既存データベースへの再投入は避けてください。

計算サービスが未設定または停止中の場合、新規実行時にエラーを表示します。別の計算モデルへの自動切り替えは行いません。

## 結果データの読み方

表示する参照輪郭は、入力画像から得た輪郭です。計算エンジン内部の重要度分布とは別のデータで、内部の分布や制御パラメータは応答に含みません。

- **ステップ**：採用した配置のステップと、実際に計算したステップを別々に記録します。再生は採用時点までです。処理時間の上限に達した場合は、その旨を表示して得られた結果を返します。
- **座標**：セル中心を整数で表し、xは右向き、yは下向きです。描画上の点の大きさは、実機の半径を示しません。
- **再生履歴**：台数に応じてフレームを間引き、先頭と採用時点を保持します。保存結果のサイズ上限は1.8MBです。
- **評価値**：同じ画像・解像度・モデルで比較してください。旧LloydモデルのHと現行モデルの輪郭誤差は異なる指標のため、モデルをまたぐ差分は表示しません。画像処理の実装が異なるため、MATLABでの計算結果との数値一致は保証しません。

## デプロイと保存データの管理

公開アプリはGitHubの`main`ブランチからVercelへ自動デプロイします。計算サービスは非公開の別プロジェクトとして管理します。`/api/health`でアプリとデータベースの応答を確認できます。

公開保存の上限は200件です。超過時は古い保存結果から整理し、初回のお手本は整理対象から除外します。

保存結果の削除には、保存時にブラウザへ発行した所有者トークンを使用します。アカウントによる本人認証は実装していません。
